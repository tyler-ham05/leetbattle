# Ladder matchmaking queues

## Description
Serves US-7. Players can start a match from a new "Ladder" page by joining a 1v1, 2v2 or 3v3 queue. When the queue has enough players, a match is created straight away in GameService, skipping the lobby.

## Specs
- New QueueService (port 4005) holds one queue each for 1v1, 2v2 and 3v3.
- When a queue has 2×N players, QueueService takes the first 2×N in join order, splits them into two teams of N, and calls GameService `PUT /game` with `{ players: [{ userId, displayName, team }] }`. This is the same payload LobbyService sends.
- The match opens on the ban phase. Players are sent the `gameId` and taken to the game.
- QueueService never calls LobbyService.
- Matches in different queues can start at the same time. Within one queue, taking players out is protected by a lock, so no player lands in two matches and no two matches take the same players.
- The front page gets a "Ladder" button that opens a new Ladder page listing the three queues.
- UI should have a button that allows players to leave queues when waiting for one
- A player can be in at most one queue. They can leave the queue before a match is found.

## Requirements
- QueueService calls GameService directly and never calls LobbyService.
- Joining a queue requires a signed-in user. The user's identity comes from their auth token, not from the request body.
- If GameService fails to create the match, the players go back to the front of the queue in their original order and see an error.
- A player in a queue can't join another queue or the lobby until they leave or get matched.
- New service tests go in `service/QueueService/test/` (add this folder to the test directories in AGENTS.md). Frontend tests don't touch backend services.
- Use only the theme classes in docs/frontend/theming.md.

## Acceptance criteria
1. The front page shows a "Ladder" button that opens the Ladder page.
2. The Ladder page shows 1v1, 2v2 and 3v3 queues.
3. When 2 players join the 1v1 queue, both are taken to the same new game on the ban phase.
4. When 4 players join the 2v2 queue, a game is created with two teams of 2.
5. When 6 players join the 3v3 queue, a game is created with two teams of 3.
6. With fewer players than needed, no game is created and the players stay waiting.
7. If a player tries to join another when they are already in one, they will be removed from the previous queue and instead be added to the new queue that they wanted to join
8. A player who leaves a queue is not put into a match.
9. When 4 players join the 1v1 queue at the same time, two separate games are created, each with 2 different players.
10. LobbyService is never called when a ladder match starts.
11. If GameService fails, the players stay queued in their original order and see an error.

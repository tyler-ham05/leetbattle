# Ladder arena cards and Run/Submit busy feedback

## Description
Serves US-10 (Polished Match Experience, #177). The Ladder page becomes three arena cards (1v1, 2v2, 3v3) that show the queue filling seat by seat, and finding a match plays a short reveal and a 2-1 countdown before the game opens. In the editor, Run and Submit show that they are working the moment they are clicked, and the result lands on the button itself: a nod for a pass, a shake for a fail.

## Specs

### Ladder (`app/ladder/page.tsx`)
- **Heading:** "Ladder" with "Queue for a 1v1, 2v2 or 3v3 match" under it, centered. While queued it reads "Finding players" with "Keep this tab open, the match starts the moment the seats fill".
- **Arena cards:** one card per mode, side by side (stacked on a phone), everything centered: the mode in large mono type, a thin bar per seat (2, 4 or 6) filled for each player waiting, "N of M players", and a full-width "Join <mode>" button. Seat bars are bars, not dots.
- **Queued:** the player's card lifts slightly and a light runs around its edge; the other cards fade back but can still be clicked to switch queues. The card shows a mono timer counting up from 0:00, and its button becomes "Leave queue".
- **Match found:** the other two cards slide out to their sides and fade; the chosen card glides to the middle and grows slightly. Its seat bars turn into the two team colors (first half `--lb-primary`, second half `--lb-secondary`) with "Your team" / "Rival team" under them ("You" / "Rival" in a 1v1). The heading area shows "Match found" and a 2-1 countdown in the lobby's digit style, then the page opens `/game/<gameId>`.
- **Countdown length:** 2 seconds, because GameService starts the match 5 seconds after creating it whether or not everyone has joined. A longer countdown would need GameService's join wait raised.
- **Copy:** no trailing periods. The QueueService error alert stays as it is.

### Run and Submit (`app/editor/components/submit-bar.tsx`)
- **Busy:** the label changes to "Running" / "Judging" and gently fades in and out, and a light runs around the button's edge. No spinner. The button keeps its size, its full color and its accessible name ("Run" / "Submit"); the other button greys out as today.
- **Pass:** Run shows "Passed" (every case Accepted); Submit shows "Accepted". The button nods twice and a check mark draws itself.
- **Fail:** Run shows "N failed"; Submit shows "Wrong" for Wrong Answer and "Error" for any other verdict (runtime error, time limit, output limit). The button turns the danger color and shakes, the same shake as a wrong password.
- **Size:** idle and busy buttons stay at today's size. Only while a result is shown does the button grow to fit it, then it settles back.
- **Timing:** the result stays on the button for 1.5 seconds, then the button returns to "Run" / "Submit". Clicking or using a shortcut during that time starts the new action at once.
- **Request failed:** if the request itself fails (no verdict), there is no nod or shake; the button goes straight back.

### Motion
- New animations live in the MOTION section of `app/globals.css`, move with `transform` / `opacity` only (the button's width change is the one exception), and each has a `prefers-reduced-motion: reduce` override: no edge light (a static primary edge instead), no nod, shake, slide or countdown pop.
- `docs/frontend/animation.md`: the Busy states row describes Run/Submit's new style, and a row is added for the Ladder match reveal.

## Requirements
- No new dependencies and no backend changes.
- Use only the theme classes defined in `docs/frontend/theming.md`. No decorative dots.
- Frontend tests (`frontend/test/`) do not touch backend services; one expect per test.
- Existing US-7-T-2 Ladder tests and busy-indicator tests are updated where this task changes the behavior they check (listed in the test pseudocode).

## Acceptance criteria
1. The Ladder shows three arena cards with seat bars and "N of M players" for each queue.
2. Joining a queue marks that card as queued with a running timer and a Leave queue button, and the player can switch queues.
3. A found match plays the reveal and a 2-1 countdown, then opens the game.
4. Run and Submit show they are working the moment they are clicked, with no spinner.
5. A pass nods and a fail shakes, with the result named on the button for 1.5 seconds.
6. Every new animation is turned off or calmed under reduced motion.
